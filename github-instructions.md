# GitHub Copilot & Agent Instructions — InvenTree QE Pipeline

This document defines the instructions for GitHub Copilot, GitHub Agents, and AI-assisted workflows operating within this repository. 

Whenever executing quality engineering tasks in this project, **do not attempt to generate all artefacts in a single unconstrained prompt**. Instead, you must strictly follow the multi-agent pipeline and **call `agents\system-instructions.md` in turn** for each specialised role.

---

## Architecture & Agent Pipeline Overview

The QE pipeline consists of specialised agents working in a strictly orchestrated sequence. Each agent receives structured input from the preceding agent and produces a verified artefact for the next:

```
┌─────────────────────────────────┐
│   Agent 1: Requirements Analyst │  <-- calls agents\system-instructions.md#agent-1--requirements-analyst
└────────────────┬────────────────┘
                 │ requirements_brief (JSON)
                 ▼
┌─────────────────────────────────┐
│   Agent 2: Test Design Engineer │  <-- calls agents\system-instructions.md#agent-2--test-design-engineer
└────────────────┬────────────────┘
                 │ test_catalogue (JSON)
        ┌────────┴────────┐
        ▼                 ▼
┌─────────────────┐  ┌─────────────────┐
│  Agent 3: API   │  │  Agent 4: UI    │  <-- calls agents\system-instructions.md#agent-3 / #agent-4
│  Automation     │  │  Automation     │
└────────┬────────┘  └────────┬────────┘
         │ Playwright API     │ Playwright UI (POM)
         └────────┬───────────┘
                  ▼
┌─────────────────────────────────┐
│   Agent 5: QA Lead Reviewer     │  <-- Quality Gate & Verification
└─────────────────────────────────┘
```

## Sequential Execution — Calling Agents in Turn

When processing instructions or generating test artefacts, the agent must load and execute the system prompts defined in [`agents\system-instructions.md`](agents/system-instructions.md) step-by-step:

### Step 1: Call `agents\system-instructions.md#agent-1--requirements-analyst`
* **Role**: Senior Quality Engineer — Requirements Analyst
* **System Instruction Reference**: See section `## Agent 1 — Requirements Analyst` in [`agents\system-instructions.md`](agents/system-instructions.md)
* **User Prompt Template**: See `Prompt 1` in [`agents\prompts.md`](agents/prompts.md)
* **Task**:
  - Ingest InvenTree Part domain requirements (`/api/part/`, `/api/part/category/`, and UI flows).
  - Define functional areas (Create, Read, Update, Delete) and business rules.
* **Input**: InvenTree documentation / API specifications.
* **Expected Output**: Structured `requirements_brief` JSON object adhering to the schema defined in `agents\system-instructions.md`.
* **Constraint**: Must NOT generate test cases — output feeds directly into Step 2.

---

### Step 2: Call `agents\system-instructions.md#agent-2--test-design-engineer`
* **Role**: Senior Quality Engineer — Test Design Engineer
* **System Instruction Reference**: See section `## Agent 2 — Test Design Engineer` in [`agents\system-instructions.md`](agents/system-instructions.md)
* **User Prompt Template**: See `Prompt 2` in [`agents\prompts.md`](agents/prompts.md)
* **Task**:
  - Ingest the `requirements_brief` generated by Step 1.
  - Generate comprehensive manual test cases covering UI and API dimensions.
  - Cover happy paths, boundary conditions, and negative/error scenarios for every CRUD operation.
* **Input**: `requirements_brief` JSON from Step 1.
* **Expected Output**: Structured `test_catalogue` JSON and corresponding markdown catalogues:
  - [`test-cases\api-manual-tests.md`](test-cases/api-manual-tests.md)
  - [`test-cases\ui-manual-tests.md`](test-cases/ui-manual-tests.md)
* **Constraint**: Must NOT generate automation code — output feeds into Steps 3 and 4.

---

### Step 3: Call `agents\system-instructions.md#agent-3--api-automation-engineer`
* **Role**: Senior SDET — API Automation Engineer
* **System Instruction Reference**: See section `## Agent 3 — API Automation Engineer` in [`agents\system-instructions.md`](agents/system-instructions.md)
* **User Prompt Template**: See `Prompt 3` in [`agents\prompts.md`](agents/prompts.md)
* **Task**:
  - Ingest the API test catalogue from Step 2.
  - Generate production-ready Playwright + TypeScript API automation scripts.
* **Input**: `test_catalogue` JSON (API test cases) from Step 2.
* **Target Directory**: [`automation\api\`](automation/api/)
  - Test files: `automation\api\tests\*.api.spec.ts`
  - Reusable client: `automation\api\helpers\api-client.ts`
* **Rules**:
  - Use Playwright built-in `request` fixture (no unnecessary HTTP libraries).
  - Use `test.beforeAll` for token authentication.
  - Clean up created entities in teardown fixtures (`test.afterEach` / `test.afterAll`).
  - Read environment variables via `process.env` (configured via `.env`).

---

### Step 4: Call `agents\system-instructions.md#agent-4--ui-automation-engineer`
* **Role**: Senior SDET — UI Automation Engineer
* **System Instruction Reference**: See section `## Agent 4 — UI Automation Engineer` in [`agents\system-instructions.md`](agents/system-instructions.md)
* **User Prompt Template**: See `Prompt 4` in [`agents\prompts.md`](agents/prompts.md)
* **Task**:
  - Ingest the UI test catalogue from Step 2.
  - Generate production-ready Playwright + TypeScript UI automation scripts using the Page Object Model (POM).
* **Input**: `test_catalogue` JSON (UI test cases) from Step 2.
* **Target Directory**: [`automation\ui\`](automation/ui/)
  - Page objects: `automation\ui\pages\*.ts` (`LoginPage`, `PartsListPage`, `PartDetailPage`, `PartFormPage`)
  - Test specs: `automation\ui\tests\*.spec.ts`
* **Rules**:
  - Strict adherence to Page Object Model architecture.
  - Use robust user-facing locators (`getByRole`, `getByLabel`, `getByTestId`).
  - Independent tests with automated setup/teardown.

---

### Step 5: Call QA Lead Reviewer / Eval Quality Gate
* **Role**: Principal SDET / QA Lead Reviewer
* **System Instruction Reference**: [`agents\agent-05-qa-lead-reviewer.md`](agents/agent-05-qa-lead-reviewer.md) and [`agents\agent-06-eval-judge.md`](agents/agent-06-eval-judge.md)
* **User Prompt Template**: See `Prompt 5` in [`agents\prompts.md`](agents/prompts.md)
* **Task**:
  - Verify generated test code against quality gates (type checking, linting, assertion completeness, coverage).
  - Produce quality gate status: `PASS`, `FAIL`, or `PARTIAL`.

## File and Security Conventions

1. **Environment Variables**:
   - Never commit sensitive tokens or passwords. All secret variables must be kept in `.env` files.
   - Refer to `.env.example` in each subproject for template configurations.
2. **Repository Consistency**:
   - Any modifications to agent definitions or system prompts must be reflected in [`agents\system-instructions.md`](agents/system-instructions.md) and [`agents\agent-configs.json`](agents/agent-configs.json).
3. **Execution Verification**:
   - Tests generated by Agents 3 and 4 must compile and pass TypeScript validation (`npm run build` or `npx tsc --noEmit`) and be runnable via `npx playwright test`.
